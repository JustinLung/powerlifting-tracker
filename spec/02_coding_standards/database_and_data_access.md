# Database and data access standards

[Fact] No database exists. [Proposed] These rules assume PostgreSQL + Drizzle ([ADR-007](../00_meta/decision_log.md#adr-007-postgresql--drizzle)). If a different stack is chosen, update this file in the same change. The architecture is described in [api_and_data_access.md](../01_architecture/api_and_data_access.md), and the entities in [data_model.md](../01_architecture/data_model.md).

## Schema

- **DB-001.** The schema is defined in TypeScript under `lib/server/db/schema/`, with one file per aggregate.
- **DB-002.** Use snake_case for table and column names and singular table names (`performed_set`).
- **DB-003.** Primary keys are UUIDs, generated by the database (`gen_random_uuid()`) or the application (UUIDv7 if index locality matters).
- **DB-004.** Every foreign key is declared with an explicit `ON DELETE` behavior. Training history uses `RESTRICT` by default, so that cascading deletes cannot erase performance data.
- **DB-005.** Weights are `numeric(6,2)`, RPE is `numeric(3,1)`, and percentages are `numeric(5,2)`. Never use floats for logged values.
- **DB-006.** Statuses use Postgres enums or `text` with a `CHECK` constraint. Pick one style in F-00 and apply it everywhere.
- **DB-007.** Invariants live in the database when they can be expressed there: unique active relationship, unique active program, one fulfilment per prescribed set, `CHECK (reps_min <= reps_max)`, and so on.
- **DB-008.** Index every foreign key and every `athlete_profile_id` used for authorization.

## Migrations

- **DB-010.** Generated SQL migrations are committed. Never edit a migration that has already been applied to a shared environment. Add a new one instead.
- **DB-011.** Data that the app depends on (system exercises) is loaded by an idempotent seed script, not by ad-hoc SQL.
- **DB-012.** Destructive migrations (drop or rename a column) require a plan section describing compatibility ([plan template](../features/_template/plan.md)).

## Queries

- **DB-020.** Only `lib/server/dal/**` imports the DB client. Lint enforcement (`no-restricted-imports`) is added in F-00.
- **DB-021.** Select explicit columns for DTOs. Avoid `select *` into client-bound data.
- **DB-022.** Avoid N+1 queries. Load a session with its prescriptions and sets using joins or relational queries, not loops.
- **DB-023.** Use transactions for multi-row writes: reorder, duplicate week, complete session, and confirm upload plus status updates.
- **DB-024.** Every query on athlete data filters by an authorized `athlete_profile_id` that was resolved server-side (AUTH-004).
- **DB-025.** Use parameterized queries only. Use raw SQL fragments only through the ORM's `sql` template tag.

## Environments

- Use separate databases for local, preview, and production. Tests use a disposable database ([testing.md](testing.md)).
- Connection strings come from environment variables. They are never committed and never logged.
